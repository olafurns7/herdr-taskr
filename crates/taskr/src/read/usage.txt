usage: taskr <command> [args]
worker:       start | got ATTEMPT_ID | note TEXT | ready TEXT --report PATH [--kv K=V]... | ask TEXT [--blocking] [--owner] | done [TEXT] | fail TEXT
              note TEXT [--owner] --as ID | ask TEXT --owner --as ID   (a root orchestrator: no parent, no launch; note --owner requires TASKR_TASK unset)
              ask [TEXT] --owner --question JSON [--dialog] [--blocking]   (a structured owner ask; the summary is built from the JSON, TEXT is context)
orchestrator: new NAME --role ROLE [--parent ID] [--planned] ... | launch ID --provider P --model M --effort E | prompt ID (--file PATH | --text TEXT) [--as SENDER_ROOT] [--push | --pane] [--receipt-timeout MS] [--confirm [--confirm-timeout MS]] | message status EVENT --as SENDER_ROOT
              answer ASK_ID TEXT [--prompt [--confirm [--confirm-timeout MS]]] | answer ASK_ID --withdraw TEXT --as ID | close ID [--outcome accepted|reworked|rejected|abandoned] [--clean-tmp]
outcomes:     accepted (work taken as delivered), reworked (taken after a fix round), rejected (not taken), abandoned (stopped before a result)
after:        after TARGET --as ID [--on KINDS] [--keep] | after --list --as ID | after --cancel SUB_ID   (TARGET: a task id, pr:N or pr:owner/repo#N; fires an `after` event into the root's inbox)
delivery:     delivery new EVENT --adapter NAME [--as ID --session GEN] [--fence N] | delivery submitted ATTEMPT [--as ID --session GEN] | delivery received ATTEMPT [--as ID --session GEN] | delivery ls [--as ID] [--open]   (a worker uses TASKR_TASK and TASKR_LAUNCH; GEN is the root's latest adopt event id, 0 before any adopt; never acks)
consumer:     consumer take --holder NAME --ttl MS [--force] [--as ID --session GEN] | consumer renew --fence N --ttl MS [--as ID --session GEN] | consumer release --fence N [--as ID --session GEN] | consumer show [--as ID]   (an opt-in inbox lease: while live, only wait/ack/delivery new with its --fence consume)
tmp policy:   set ROOT tmp.cleanup=on-close|root-close|keep (default on-close; counts toward 20 refs; root only)
plan:         next ID TEXT | next ID --clear | set ID KEY=VALUE... (KEY= deletes) | decide --as ID TEXT | decide --as ID --revoke EVENT_ID
documents:    doc set ID goal|plan [--name NAME] --file PATH (any host) | doc ls ID [--tree] [--kind K] [--versions] [--limit N] | doc get DOC_ID | doc rm DOC_ID --purge | doc backfill [--tree ID] [--dry-run] (any host)
handover:     handover --as ID [--note TEXT] [--out PATH] | adopt ID [--workspace W --tab T --pane P]   (Markdown on stdout)
inbox:        wait [--as ID] [--for KIND[,KIND...]] [--from NAME|ID]... [--ack EVENT_ID] [--timeout MS] [--scan-quota] [--fence N [--session GEN]] | ack EVENT_ID --as ID [--fence N [--session GEN]]
inbox read:   inbox [--as ID] [--limit N]   (raw and non-consuming: the caller's events after its ack cursor, oldest first, default 20, 1 to 200; never offers, receipts or acks, no coalescing or --for/--from, so the first row is not necessarily what wait returns next)
mcp:          mcp [--channel] | mcp --as ID --session GEN [--channel]   (a local stdio MCP server, revision 2025-06-18, bound at start to TASKR_TASK/TASKR_LAUNCH or to a root's pinned generation; tools run this binary)
push:         push codex [--codex-bin PATH] | push codex --as ID --session GEN --codex-thread UUID --codex-home PATH [--codex-bin PATH]   (a local sidecar: holds the inbox lease and queues each event into the bound Codex thread with `codex queue`; stdin EOF stops it)
hooks:        hook <harness> <event> (JSON on stdin)
read:         status [--tree ID] [--all] | asks [--open] [--tree ID] [--owner] [--limit N] [--all] | log ID [--tree] [--since EVENT_ID] [--before EVENT_ID] [--limit N]
              campaign ID [--page N] [--all]   (campaign detail; --all includes closed lanes)
              glance [--watch [--every 5s]] | glance --brief [--since EVENT|DURATION]   (owner snapshot; --watch is the live split-pane view; --brief prints it once as text for the hub)
              slotr   (the hub's slotr pools, holders and queue as JSON; available:false when slotr cannot be read)
              notes [--owner] [--root ID] [--since EVENT|DURATION] [--limit N]   (root notes, newest first; default 48h, 50)
tmp:          tmp ID [--mkdir]   (this host's lane tmp dir <base>/<root-id>/<task-id>, base $TASKR_TMP_BASE or /tmp/taskr-<uid>; --mkdir makes them 0700)
search:       search QUERY [--root ID] [--kind K] [--limit N] [--raw]   (documents and decision/ask/answer/note; default 20, max 100)
daemon:       daemon [--stay] [--once] [--status] [--restart]   (the Herdr plugin's event bridge and the hub server; one per HOME)
info:         version | help [CMD]
client:       --request-key KEY <command> [args]   (with a server.url: retry a command whose answer was lost)
spool:        spool ls | spool send | spool rm SEQ|FILE   (client-local queued records)
format:       compact by default; --json or TASKR_FORMAT=json selects legacy JSON (handover/adopt stay Markdown)
